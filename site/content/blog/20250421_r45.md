## Getting a personal R-verse 

R has released the version `4.5` with some *nice to have* upgrades (see [Setphen' summary](https://blog.stephenturner.us/p/r-450-bioconductor-321) for more). Updating to a new R major version, however, is always a pain since you don't only need to re-download and re-install R itself but the packages cannot really be migrated in a obvious way.

An approach that I used in the past is to list all the installed packages in one version (see below) and try to install them in the next one.

```R
as.data.frame(installed.packages()) |> 
	dplyr::pull("Package") -> pkgs
# + try to install them somehow
```

This is not the ideal solution for several reasons: **First**, some packages will come from bioconductor, some from github, some from CRAN, and this information is not directly available from the `installed.packages()` function. **Second**, realistically I don't really need all of the packages that I have installed, just the ones that are useful.

A solution that I found in Stephen's blog is to create a sort of *verse*-like package that depends on a list of packages that you want to install all at once, in a similar manner that [tidyverse](https://www.tidyverse.org/) installs `readr`, `ggplot2`, `tidyr`, ... 

**What do I put in though?** A rule that I came up with is that If I used the package every day, it goes in, if I use it every other week, it goes in too. Only the ones I don't remember why I have them installed should be left out. This rule might be slightly too generous for some but due to the latest parallel install feature in `R/4.5`, installing a large number of packages won't take an eternity anymore 🎉.

**How to include bioconductor deps**. I had some problems installing pacakages from bioconductor. Although this approach through `Remotes:` should work, it didn't seem to recognise them for me. A solution that appears more simple and has worked great so far is through adding a `Bioviews:` empty field (as in below) in the `DESCRIPTION` file. This aparently opens the bioconductor repository for a R package and things that it depends on but are located in bioconductor can still be accessed.

```r
Depends:
    R (>= 3.3.0)
biocViews:
Imports:
    methods,
    snpStats,
    dplyr
```

**How to include a github project.** For this I did need to use the `Remotes:` code. The notation expects github by default (see here) but other providers, such as gitlab, are also available. See below 

```r
Depends:
    R (>= 3.3.0)
biocViews:
Imports:
    methods,
    snpStats,
    dplyr
Remotes:
	...
```

**So how do I use it now?** Once you have your list of R packages, you would need to first install remotes repo and then install your verse from github.

```R
install.packages("remotes")
remotes::install_github("davidmasp/dmpverse")
```

**Using a branch for multiple [universes](https://www.tidyverse.org/).** Here the idea is to push multiple branches in your git repo (e.g. you can create a minimal one for a dcoker container) and then use them in different situations where they are suited. I haven't decided yet to which extent this is a good model to keep multiple docker images for R as it might get too complicated very fast but it's an idea I might explore in the future.

Here you can find [Stephen's](https://www.tidyverse.org/) and [mine](https://www.tidyverse.org/) for inspiration.
